# 深海青綠設計規範

版本 1.0.0，2026-10-07。設計目標是清楚、沉穩、帶工程感的個人展示頁。色彩沿用使用者選定的深海青綠，不延伸為霓虹、黑金或大面積漸層風格。

## 1 視覺適用範圍

原生文字負責介紹、作品說明、標題與連結；自訂 SVG 負責橫幅、統計及圖表。GitHub 的背景、側欄、字型及原生連結由平台控制，不能用此規範改動。SVG 維持固定深色、不透明背景，在 GitHub 明暗模式下皆可讀。第一版不增加第二套亮色卡片。

設計參考：[離線預覽](../design/deep-sea-mint-preview.html)。該 HTML 使用 CSS 方便檢視設計，不是部署程式，也不代表 GitHub 能執行相同排版。

## 2 色彩

正式數值以 [tokens.json](../design/tokens.json) 為單一來源；修改時同步規範與預覽。

| Token | 色碼 | 用途 |
| --- | --- | --- |
| background | `#101A22` | SVG 底色 |
| surface | `#192833` | 卡片表面 |
| primary | `#48D6B0` | 重點數字、當前貢獻、主圖表 |
| secondary | `#85AEFF` | 第二資訊層、技術標籤、次要資料系列 |
| text | `#E6EDF3` | 主要文字 |
| textMuted | `#AFBFCD` | 期間、單位、說明 |
| border | `#344754` | 裝飾性分隔線，不承擔唯一辨識功能 |
| warning | `#F0C674` | 資料不完整或維護提醒，搭配文字 |
| danger | `#FF8F9C` | 管理與預覽錯誤，搭配原因 |

底色與表面合計約占 80%，文字與中性色約占 15%，青綠及藍色約占 5%。比例是視覺方向，不需逐像素計算。不要為每個元件加彩色邊框；以標題與間距分組。

語言圖表最多六類，顏色依排序套用 primary、secondary、`#B8A1E3`、`#E8BC78`、`#E58FA8`、`#A9BAC7`；不是 GitHub 官方語言色。每次產生以語言名稱與名次固定當次映射，圖例及圖形必須一致，語言名次改變時允許色位變化，不把顏色當作長期語言 ID。

日曆色階依 NONE、FIRST、SECOND、THIRD、FOURTH 使用 `#263743`、`#24594F`、`#2B826D`、`#38AE8D`、`#48D6B0`。這些是分級色階，圖例與文字摘要補足對比；不是所有相鄰格都需達到文字對比。

## 3 字體與文案

SVG 優先系統字型 `Segoe UI, Noto Sans TC, Microsoft JhengHei, sans-serif`；數值 `Consolas, SFMono-Regular, monospace`。不外連字型，不將全部文字轉為圖片路徑，以控制大小並保留可檢查文字。不同系統字型寬度不同，實作必須保留餘裕並檢查長字串。

以下為 360 px 卡片座標字級：標題 22、主數值 32、內文 18、標籤與期間 18；權重 400、500、600。標籤使用 18 px。實際 GitHub 的 320 px 視窗可用卡片寬約 238 px，縮放後約 11.9 px；375 px 視窗約 14.6 px。完整數據同時以 GitHub 原生文字表格提供，讓小螢幕可展開閱讀。重要日期與圖例皆採此字級。行高基準 1.5；大數值不低於 1.2。使用完整數字與千分位，不把不同值都縮成相同的 1k。

繁體中文描述用短句，不宣稱未確認的職稱、專家身分、技能熟練度或成效。標題以「精選作品」「技術與方法」「GitHub 動態」為主。英文作次要標籤，不要全頁大寫。

## 4 間距與幾何

間距階梯為 4、8、12、16、20、24、32、48 px。卡片內距 20 px，元件間距 16 至 24 px，段落間 32 px。卡片圓角 14 px；內部標籤圓角 6 px。邊框 1 px，強調線 3 px；不使用厚陰影、毛玻璃或持續動畫。

可讀區優先：一張圖放不下時增高或拆圖，不縮小文字。主要卡片寬 360 px；外框含在 viewBox 內。所有 SVG 有明確 width、height、viewBox、title 及 desc，不放 script、foreignObject、外部 image 或動畫。

## 5 首頁內容順序

| 順序 | 內容 | 呈現 |
| --- | --- | --- |
| 1 | 姓名與一句話介紹 | 原生 H1 與文字，避免圖片失效時首頁空白 |
| 2 | 青綠橫幅 | 360 × 180 SVG，短句與幾何分隔，屬裝飾性補強 |
| 3 | 精選作品 | 2 至 3 個原生小標題與簡介，明確 Repo 及選用 Demo 連結 |
| 4 | 技術與方法 | 短清單及至多 6 個已有依據的技術標籤 |
| 5 | GitHub 動態 | 快照文字摘要、統計卡片與可展開詳細資料 |
| 6 | 公開聯絡 | 只顯示已核對的入口；沒有資料則省略 |

不把整頁做成單張長圖，不在文字 README 模擬側欄、導覽列或不能操作的搜尋列。

## 6 元件規格

| 元件 | 基準尺寸 | 內容與狀態 |
| --- | --- | --- |
| Hero | 360 × 180 | Jacky、簡短標語、細青綠線；重要文字於 README 重複提供 |
| Activity | 360 × 440 起 | 期間文字、5 項期間指標、目前專案及 Stars，2 欄排列；高度隨換行增加 |
| Streak | 360 × 260 起 | current、期間最長、截至今日或昨日、邊界至少值；不把裝飾圓環當完成率 |
| Languages | 360 × 440 起 | 圓環上方、圖例下方，最多六類；原始 bytes 放展開表格 |
| Monthly | 360 × 300 起 | 12 柱、零起點、單位「貢獻」、3 個主要月份刻度；完整值放文字表格 |
| Calendar | 360 × 220 起 | 完整期間、週欄、日格、四級圖例、資料日期 |

若活動數字超過 8 字元則改為單欄或增高；不可裁切。語言標籤太長時圖例換行；名稱與比例分開對齊。月圖最高值為 0 時畫空軸並寫「此期間無貢獻」，不除以零。

日曆內容區寬 320 px，最多 54 週欄，每欄 5 px 格子加約 0.9 px 間距，總寬不超過 320。週從星期日開始，期外填透明格；資料日期依 API 回傳，不能把期外空位算零貢獻。月份標籤只顯示不重疊的主要月份，完整日期放文字替代。圖格不要求逐格互動。

第一版每張 360 px 圖片使用獨立段落垂直排列。這是跨桌機與手機的可靠基線，不依賴 CSS grid 或 HTML table。日後若改成雙欄，需另外通過 GitHub 真實渲染檢查；本機兩欄效果不能直接視為可發布。

## 7 互動與無障礙

第一版互動只有原生 HTTPS 連結與 `<details><summary>` 展開區。SVG 圖片內不放必須可點擊的按鈕；所有 Repo、Demo、聯絡入口都使用原生 Markdown 連結。沒有可用連結就不顯示入口，不以 `#` 假裝可操作。

每張統計圖提供 alt，包含期間與主要意義；同一個 details 內提供當次快照的總數、各月數值、語言 bytes 及必要每日資料。圖片與替代文字由同一份快照生成。鍵盤可逐一到達原生連結及 summary；彩色圖例同時有文字。重要內容不依賴 hover、動態效果或色相辨識。

## 8 明暗模式與相容性

GitHub 白色背景下，深海青綠卡片仍維持深色與不透明圓角邊界；不偽裝成整頁背景都變深色。GitHub 深色背景下，卡片以 surface 與細邊線區隔。原生文字與連結跟隨 GitHub 主題，不要求與 SVG 字體完全一致。

在 320、375、768、1280 px 檢查 README。GitHub 圖片應受容器寬限制；必須在實際平台驗證此行為，不用預覽的 CSS 補救平台不支援的排版。若平台未如預期縮放，改用原生支援的 img 寬度與較窄輸出，重新驗證。

## 9 視覺驗收

同一類元件的標題、日期、內距及圖例位置一致。對比工具驗證 primary、secondary、text、textMuted 對 surface 的實際比值；低對比 border 只可用於裝飾。圖表不能出現被遮住的標籤、靠邊被裁掉的字或不明比例圓環。所有數字皆以真實資料或明確標示「示意」的 fixture 產生，不能把預覽假值發布到個人首頁。
